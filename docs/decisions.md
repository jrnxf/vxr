# Decisions

What has been settled for vxr so far, and why. Newest context first within each section.

## Identity

- Name: **vxr**. Description everywhere: **fast voxel scenes** (short, terse, all lowercase).
- Packages: crate `vxr` on crates.io; npm `@jrnxf/vxr` (scoped, so it cannot be squatted). Neither is published yet.
- Repo is private for now.

## Product

- An open-source voxel scene editor with MagicaVoxel's feel and none of its limits, plus a one-tag web embed.
- The wedge, from `docs/market-research.md`: MagicaVoxel is loved but closed source, stalled, Windows-only in its current build, Intel-only on Mac, has no Linux build, and caps models at 256^3. Nobody owns voxel web embeds.
- v1 must keep what MagicaVoxel users love: results in minutes, the hand-sculpting feel, a palette-first workflow, a beautiful built-in renderer.
- v1 must fix the loudest complaints: the 256^3 cap, render being a separate mode, platform gaps, capped undo.
- Out of v1: collaboration, rigging, AI generation (the v1 assistant edits through tool calls, it does not generate), accounts, cloud storage.
- AI (in v1): `docs/research/ai.md` recommends one typed scene edit API (`vxr-ops`) shared by a bring-your-own-key assistant (tool calls, never a generator; every change previewed and applied as one undo step) and a `vxr mcp` stdio server (files on disk first, a running desktop app over a local socket second). Keys stay on the user's machine: OS keychain natively, the tab's memory by default in the browser, with providers called directly (all of Anthropic, OpenAI, Gemini, OpenRouter and local servers allow browser calls), so it keeps the no-server rule. The owner's answers so far (2026-10-25): the assistant and `vxr mcp` both ship in v1; the assistant is a docked chat panel with Cmd-K "Ask AI" as a shortcut into the same conversation, small changes review in a card and bigger ones in a step list; live `vxr mcp` edits apply straight away, one undo step each, shown on screen with Undo and Stop; no hosted key or paid tier is planned yet; scripting is passed on for now, and its language is decided when script mode is planned; browser keys have three homes and are never stored where the server can read them: this tab only (default), remember in this browser (encrypted on the device, off by default, with a warning), and later sync to my account (encrypted in the browser with a passphrase only the user knows before upload, so D1 holds an unreadable copy; comes with Google login, when sharing and embeds are built), while keeping keys in a server-readable database was rejected (one breach would leak every key, and the operator would hold everyone's keys); code on vxr.jrnxf.co can still read a key while the page uses it, which the strict content security policy and spend-capped keys limit. Still waiting for the go; the risk tests are the AI phase in `docs/plan.md`.
- Feature gaps against MagicaVoxel are tracked in `docs/research/magicavoxel-gap.md`, ranked by which loved trait they serve. The order to close them: lossless save first (without it, saving an opened MagicaVoxel scene loses its materials, layers and cameras, so no existing user can switch), then palette editing and the renderer (the two loved features vxr lacks most visibly), then line and center brushes with XYZ mirror, then selection and transform. Shaders and animation wait: they are loved by fewer users and the shader runtime should share the edit API the AI work will need.

## UI: Hybrid (direction D)

Picked from four directions in `ui-directions.html` (in the `design-references` GitHub release) (A Studio, B Sketch, C Diorama, D Hybrid).

- One small floating toolbar: add, erase, paint, pick, plus a few shapes (voxel, box, face). Single-letter keys for everything, modifiers for quick overrides (Shift erases, Alt picks), and hints near the cursor.
- The palette is always on screen. Editing a palette slot recolors every voxel using it.
- The scene tree appears only once a second object exists, so a single model stays clean.
- A live path-traced preview sits in a corner while you edit, instead of a separate render mode.
- Cmd-K command palette for everything else.
- Camera: MagicaVoxel style. Right-drag orbits, middle-drag or Shift+right-drag pans, wheel zooms toward the cursor, `.` frames the scene.

## Platform and stack

- **Desktop first, browser from the same code.** Desktop gets full GPU and CPU, no browser memory caps, and real file handling. The browser build exists for "try it from a link" and for the embed, which can only live on the web.
- Rust core on **wgpu** (Metal, Vulkan, DX12, and WebGPU in the browser). UI drawn in Rust with **egui** (test 3, below) so the same Hybrid UI runs in the window and in the browser.
- Ship order: desktop editor, then the embed (a viewer, small), then the full editor in the browser.
- The browser build will not be laggy for normal scenes: rendering runs on the GPU at near-native speed. Desktop only pulls ahead at the extreme end (huge scenes, heavy CPU remeshing, browser memory caps).
- **No server.** Rust compiles to WebAssembly and runs on the visitor's machine. The site, editor and embed are static files (free on Cloudflare); the npm package is served free by jsDelivr and unpkg. A server is only needed later for sharing or accounts, and a small Cloudflare Worker would do.
- Build and tune on a Mac with a real GPU. The prototype was built on a machine with no GPU, so its speed was never measured on hardware.

## Engine, preview, `.vox` and embed (settled by Phase 2)

Phase 1 picks from `docs/research/recommendation.md`, now confirmed or changed by the Phase 2 spikes in `spikes/` (each has a `RESULTS.md`). Measured on an Apple M4 Pro (16-core GPU) with other apps using the GPU, so times are upper bounds.

- **Engine: sparse brick map, ray marched, compacted layout by default.** 8^3 bricks with an occupancy mask; palette bytes stored only for occupied voxels (per-brick offset plus popcount). Measured 1.2 to 2.4 B per voxel on every scene tried; the dense layout used 4.3 to 8.9 B on hollow models and failed the 3 B line. Compacted costs 3 to 15% frame time. Full Retina, median: 10M voxels 4.7 ms native, 4.9 Chrome, 5.0 Safari; 100M voxels 6.9 / 7.1 / 7.4 ms. Radius-16 edits land in the next frame. Browsers loaded 300M voxels. Traversal: `trace_h` (brick steps plus a coarse 64-bit occupancy word that skips empty 32^3 cells).
- **The browser draws as fast as native.** Native wins only on CPU work (building a 100M scene: 0.66 s native, 1.3 to 2.0 s in browsers). This backs "desktop first, browser from the same code".
- **Live preview: progressive path tracing at 640x360 in the corner, passes everywhere.** It adds 2.5 to 3.8 ms per frame and comes clean in 0.3 to 1.2 s. Budget all preview work (trace, denoise, composite) at 3 ms per frame while editing and 12 ms after 300 ms idle; the idle boost is required. Write the preview into the editor image instead of a second full-screen pass. No 480x270 or pause-while-editing fallback needed.
- **UI layer: egui** (test 3, `spikes/ui/RESULTS.md`). Both builds passed: the UI adds 0.3 ms native and 0.6 ms in Chrome at 2560x1600 (line 1 ms), and every click edit drew in the next frame. egui's look matched the HTML/CSS build within 1 to 2 px at 1x and 2x; HTML is closer to the mockup only in backdrop blur and slightly lighter text. Under the rule for that night (egui wins unless its look is clearly below), egui won, and it keeps one Rust UI on desktop and web with no DOM-to-engine input routing. Costs taken on: the browser editor's shell is 812 KB brotli against 71 KB for HTML/CSS (egui 0.37's glyph rasterizer), IME needs a CJK fallback font and a positioned hidden text field in the browser, and egui has no screen-reader tree in the browser (AccessKit on desktop). The owner judged none of this in person: the call was made unattended and **the owner may overturn it** after comparing `spikes/ui/shots/egui-2x.png` with `spikes/ui/shots/html-2x.png` (regenerate them as `spikes/ui/RESULTS.md` says; they are not in git).
- **`.vox`: our own two-layer codec (raw chunks plus semantics), about 1,700 lines.** 568 of 568 real MagicaVoxel files re-save byte for byte; edits change only the chunks they must; 1 hour of fuzzing found no crash after one fixed bug. MagicaVoxel (0.99.6.2) confirms that transforms compose parent then child and that pivots are floor(size/2). The scene model needs instancing (shared nodes) from the start. MagicaVoxel clamps positions to about +-1000, so warn when exporting wider scenes. 0.99.7.x-only behaviour (version 200 overlap order, `_frm_t`) is untested: it ships only for Windows.
- **Browser:** WebGPU is required for the editor and path tracer.
- **Embed: its own crate, WebGPU only, poster-only fallback (no WebGL2).** 39.8 KB brotli for wasm, glue and loader (target 150 KB). On an iPhone 17 Pro the scene shows 217 ms after scrolling into view at 10 Mbit/s and 1.16 s on Slow 4G. The snippet puts the poster as an `<img>` inside the tag (70 ms; the `poster=` attribute alone missed the 100 ms line). The embed loads a brick-format scene file with `.vox` as the fallback: the island is 14.5 KB as bricks against 137 KB as `.vox`. A built-in WebGL2 fallback would be about 25 times the viewer. Mid-range Android is not measured.

### Open going into Phase 3

- Growing the compacted pool on the GPU instead of repacking on the CPU: today a full pool costs one hitch of 54 ms native and about 100 ms in browsers at 100M voxels.
- The native close, low view sits near the 120 fps line; a depth prepass is the likely fix.
- Not measured: M1-class Macs (estimate about 15 ms at 10M, full Retina), mid-range Android, the iOS reload memory test, MagicaVoxel 0.99.7.x.
- Longer multi-core fuzzing before the embed reads files from strangers.
- Licence (still open from `docs/market-research.md`).

## Phase 3 app

- **Workspace:** `crates/vxr-vox` (the Phase 2 codec, unchanged apart from the crate name), `crates/vxr-core` (the scene with no GPU, so it tests fast and builds for wasm32), then a renderer and the app on top. Nothing depends on `spikes/`.
- **Axes:** vxr is y-up; a MagicaVoxel voxel at (x, y, z) is the vxr cell (x, z, -y). The brick map starts at zero and the scene keeps an `origin`, so files keep their coordinates.
- **Opening a file** reads it as a world of objects (see "World editor" below): a file with one object opens in model mode on it, with the bounds at the model's exact size; a file with several opens in world mode. Up to 2048 voxels per axis. (Until Part 3 item 8 every instance was flattened into one map with 16 voxels of room on each side.)
- **Saving is lossless for opened files.** (Since Part 3 item 8 an opened file saves through `World::save_into`, below; this paragraph describes the flattened save it replaced, which `Document::set_world` still implements.) The `Scene` keeps the `vxr_vox::Document` it was opened from, and saving applies the difference between the file's world voxels and the editor's to it (`Document::set_world`, plus `set_palette` for each recoloured slot), so every chunk the edit does not need keeps its bytes and order: materials, layers, cameras, render settings, notes, names, hidden flags, animation frames, the version number and unknown chunks. An unedited save is byte-identical to the file. Erased cells are cleared in every model that covers them; added and painted cells go into the model that shows them, by the file's overlap rule (from version 200 the earlier instance wins, before it the later one); cells no model covers become new models of at most 256^3 under the root group, with a transform that undoes the root's. Only edited models' data chunks, the root nGRP (new children) and, for linked copies, an nSHP change.
  - **Linked copies split on edit.** vxr flattens every instance into one map, so an edit through one instance shows only there. To save what the user saw, an edited instance of a shared model gets its own copy of the model and its nSHP points at it; the other instances keep the original. This differs from MagicaVoxel, where editing one linked copy edits all; real instance editing comes with the world editor (Part 3 item 8).
  - **The fallback rebuilds only the geometry.** Every save is checked by re-reading the result: if the edit cannot be placed exactly (a shape node shared by several transforms, or a root that is not nTRN 0 over a group), the models and scene graph are rebuilt from the world voxels and every other chunk is still kept as is. Names, layers and hidden flags of nodes are lost in that case only.
  - A new scene still writes a fresh version 200 file (palette plus voxels, split into 256^3 models).
- **Renderer** (`crates/vxr-render`): only the compacted layout and `trace_h` came over from the engine spike; the dense layout, the other traversals, the heat map and the bench hooks stayed behind. The background is the mockups' dark radial gradient (#262b37 to #0d0f14) instead of the spike's light sky, so the translucent panels read as in the mockups. The hovered voxel is tinted in the march shader, so the cursor costs no extra pass.
- **Editing tools** (`vxr_core::tools`) follow the prototype: add puts voxels in front of the face hit, erase and paint touch only filled cells, pick takes the colour. Voxel drags fill the gaps between pointer samples; add and box drags stay on the plane of the first face; face clicks take the connected same-colour face (up to 120,000 cells). A whole press-drag-release is one undo step. Clicks that miss every voxel land on a ground plane at the bottom of the opened model (the bottom of the map in a new scene), so an empty scene can be built on. Mirror reflects across world x = 0, as in the prototype; see **Brushes** for Y, Z and the axis lock.
- **App** (`crates/vxr-app`): `Editor` holds the scene, renderer, camera and UI with no window, so the winit host and a headless `--shot` run share every code path; the browser host will reuse it. The surface uses a non-sRGB format because the march writes sRGB-encoded colour and egui then blends in gamma space, as the HTML mockups do. Fonts are read at startup from a git-ignored folder (fetched and checked by sha256) rather than committed, since together they are about 2.6 MB. Save writes back to the opened file; a new scene asks for a path.
- **Browser build** (`crates/vxr-web`): the page forwards DOM pointer, wheel, key, paste and IME events to the shared `Editor`; a second button pressed or released during a drag arrives as a `pointermove` (a chord) and is forwarded as a button change, so a chorded click neither edits nor leaves a drag stuck. It is checked end to end by `crates/vxr-web/check`, which drives the real page in headless Chrome with synthetic DOM events (through the page's own listeners), stubs only the native file dialog and the download click, and reads the result from `window.vxr.state()`. A real-mouse test is not possible headless with the screen locked; the synthetic events cover the same listeners.
- **Rail icons and labels** follow the prototype: the second group is "Brush", and the mirror button uses the prototype's glyph, which Lucide 1.x renamed from `flip-horizontal-2` to `flip-vertical-2`. `?` opens the command list, as the coach card promises.
- **Palette editing.** All 255 slots show in a grid that scrolls (the prototype's `max-height: 240px`; MagicaVoxel users need the whole palette). The Edit button (or a double-click on a swatch, or Cmd-K "Edit color") opens a colour editor beside the palette panel, built from the panel's own parts since the mockups have none: a saturation/value square with a hue bar, and hex, R, G, B, H, S and V fields. It edits the current slot, so clicking another swatch moves it there. Every change shows at once (the palette buffer is rewritten, nothing is remeshed), and one drag or one applied field is one undo step: `Scene::put_color` collects the slot's first and last colour into the open edit and `commit` closes it. The editor keeps its own HSV so the hue survives greys and black.
  - **Swap keeps the scene's look; copy recolours.** Swap (button, Cmd-K, or Cmd/Ctrl-drag a swatch onto another, as Ctrl+drag in MagicaVoxel) trades the two slots' colours and moves their voxels with them, so only the palette order changes; MagicaVoxel added this as "swap palette color without changing model, make it easier to organize palette" (0.97.2), and organising is what swapping is for. Copy (button, Cmd-K, or Cmd/Ctrl+Shift-drag) gives the target slot the colour, so voxels in the target take it. Both are one undo step, and the selection follows the colour to the target slot. A swap or copy is armed by its button and done by the next swatch click; Escape cancels.
- **Live render corner** (`vxr_render::Preview`, from `spikes/preview`): the progressive path tracer draws at 640x360 into a 320x180-point rounded panel above the undo/redo buttons (the mockup's pin 4 sits bottom right), labelled "Path trace · N spp · live". It is written into the editor's colour texture by a compute pass with rounded corners before the blit; egui draws only the border and the label, with no panel fill, so the image is not dimmed. Its backdrop is the editor's dark gradient rather than the spike's light sky (the sky still lights the scene), so the corner sits in the UI like the main view. It shares the main camera.
  - **Budget:** 3 ms per frame while input arrives, 12 ms after 300 ms without input, at most 4 samples per frame. With `TIMESTAMP_QUERY` (native, and Chrome) the trace and denoise passes are timed and read back a few frames later without waiting (a ring of 4 buffers), and the rows traced per frame follow the measured cost per row. Without timestamps a full sample is assumed to cost 4 ms, above anything the spike measured, so the budget holds. Sampling stops at 1,024 spp until the camera, the light or the scene changes, so an idle editor does not keep the GPU busy.
  - **Edits** reset only the pixels whose primary or sun ray crosses the changed box (the brick map now records the box of changed voxels, `take_dirty_box`, one voxel wider), and cap nearby pixels at 16 samples; the label's count then restarts, since it shows the least-sampled pixels. Camera, sun, sky and lens changes restart everything; exposure only re-resolves the image (it is applied after accumulation), so dragging it keeps the samples. Recolours need no reset.
  - **Toggle:** Cmd-K "Toggle render preview". No single-letter key for hiding it: the free letters are kept for the brushes and selection that come next. `R` opens the Render panel (and shows the corner), the one render key worth a letter. Clicking the corner to swap it with the main view (the mockup's note) is not built yet.
  - **Cost** on Apple M4 Pro (16-core GPU, 24 GB), island at 3024x1964, median CPU+GPU frame with a wait for the GPU: 2.00 ms without the corner, 3.6 ms with it while editing and when idle (one full 640x360 sample takes 0.44 ms by timestamps, so the 4-sample cap binds before the 12 ms budget). After the Render panel and export: 1.99 ms without, 3.65 ms editing, 4.1 ms idle (the extra uniforms and lens branch cost nothing measurable).
- **Render panel** (not in the mockups; the board lists Render as "next"): a .panel left of the render corner, bottom-aligned with it, built from the colour editor's parts. It opens from an aperture button on the corner (Lucide `aperture`, the board's Render icon), the `R` key or Cmd-K "Render settings", and Escape closes it. It holds sliders for sun direction and height, sun strength, sky light, exposure (in stops), depth of field and focus, a sun colour field, a "Show sky behind the scene" toggle, Samples (64, 256, 1K, 4K: where the corner stops and what an export traces, default 1K) and Export size (720p, 1080p, 1440p, 4K), and Export PNG. It and the colour editor share the space beside the palette and the corner, so opening one closes the other rather than overlapping.
  - **Relative lens:** depth of field (0 to 100%, lens radius up to 3% of the orbit distance) and focus (0.25 to 2 times the orbit distance, 1 focuses on the orbit target) are relative to the camera, so a setting means the same at any zoom. MagicaVoxel's click-to-focus is not built yet.
  - **Depth of field** stores samples with their own hit's colour (blurred edges mix colours), so with it on a recolour or an edit restarts the image instead of resetting only nearby pixels. Off (the default), both stay instant.
  - **Sky:** the built-in gradient sky, scaled by Sky light, lights the scene; the toggle also shows it behind the scene (tonemapped like the scene). Off, the backdrop stays the editor's gradient. A physical sky (Rayleigh, Mie, sun disk, as in MagicaVoxel 0.99.1) is a later step.
  - **Export PNG** renders the corner's view (16:9, the camera at the moment of export, so orbiting meanwhile does not restart it) with a second `Preview` at the export size, through the same path tracer and denoiser, under its own 12 ms-per-frame budget, so editing never blocks; the corner pauses and keeps its image meanwhile, and its label and the panel's button show progress (clicking it cancels). Edits made during an export reach it like they reach the corner. The result is read back without waiting (`vxr_render::gpu::Readback`, the same natively and in browsers) and encoded with the `png` crate in Rust on both targets: native asks where to save (`<scene>-render.png`), the browser downloads it. Sizes whose buffers exceed the device's limits (`Preview::fits`: 80 bytes per pixel, the largest buffer 32) are greyed out. 1280x720 at 64 spp takes 18 frames (0.18 s) on the Mac above.

- **Materials per palette slot**, as in MagicaVoxel (a material belongs to a colour slot, not to a voxel). The colour editor gets two tabs, Color and Material, rather than a third panel: the Material tab holds the type (Diffuse, Metal, Glass, Emit) and that type's sliders (metal: roughness, metalness; glass: roughness, transparency, refraction; emit: emission, power), and Cmd-K "Edit material" opens it. Each type change or slider drag is one undo step, and swap and copy of slots carry the material with the colour. Swatches whose slot is not diffuse show a small light corner.
  - **Saved as MagicaVoxel's `MATL`** (`vxr_vox::material`): the chunk id is the palette index, `_type` is `_diffuse`, `_metal`, `_glass` or `_emit`, and only the keys of the type written change (`_rough`, `_metal`; `_rough`, `_ior` as index minus 1 and `_ri` as the index, `_trans`; `_emit`, `_flux`). Every other key (`_spec`, `_weight`, `_plastic`, ...) and every slot vxr did not edit keep their bytes, so an unedited or undone save stays byte-identical. A new scene writes `MATL` only for slots that are not plain diffuse (MagicaVoxel reads a missing slot as diffuse). Newer types are read as the nearest of the four (`_blend` as metal or glass by its weights, `_media` as diffuse) and are only rewritten if edited.
  - **Rendering** is an approximation, not MagicaVoxel's exact model: metal reflects with a roughness-spread mirror direction tinted by its colour, plus a sun highlight (normalized Phong lobe) and a diffuse share by metalness; glass reflects by Schlick's Fresnel or lets the ray through straight (thin glass: no bending inside), tinting it per voxel crossed by colour times (1 - transparency), and lets tinted sun light through to shadows; emissive adds its colour times emission times 2^power times 2, and lights its neighbours through the diffuse bounce (no light sampling of emitters yet, so small bright emitters are noisy). Light passes through at most 24 glass voxels; more counts as opaque.
  - **Instant recolour kept for diffuse**: pixels whose first hit is metal or glass are stored in colour (a flag in the pixel record) and filtered only with each other; the rest stay demodulated. A recolour restarts the image only while some slot is metal or glass; a material change always restarts it.
  - **Cost** (same Mac, island, 3024x1964): 2.02 ms without the corner, 4.22 ms with it while editing, 4.32 ms idle; one 640x360 sample went from 0.44 to 0.54 ms with the material path loop on an all-diffuse scene. The corner keeps its 3 ms / 12 ms GPU budget, so heavier scenes trace fewer rows per frame rather than slowing the editor.

- **Undo** stores each action as one step: the cells it changed and the palette slots it recoloured or gave a new material (old and new values), with no cap. The brick map keeps a voxel count per palette slot, so the used-colour dots need no rescan.

- **Brushes (line, center, mirror on three axes, axis lock).**
  - **Line (L)** and **center (C)** are span shapes like box: press, drag on the drag plane, release. All four are redrawn from scratch on every pointer move (the open edit is reverted and drawn again), so the shape shows in the scene live and shrinking it gives the cells back; the release is one undo step. The stats panel shows the box size, the line length or the radius while dragging.
  - **Center is a circle on the drag plane** (MagicaVoxel's center brush is 2D on the face plane); pressing C again, or the rail button again, makes it a **sphere** around the same center. One rail button and one key keep the rail short; its icon shows which. Cells within r² + r/2 of the center are drawn, so radius 1 is a plus and small circles look round. Radius is capped at 64 (a ball of about 1.1 million cells) so live redraw stays interactive. Square-from-center and even diameters are not built: the box brush covers squares.
  - **Mirror on X, Y and Z**: M turns mirror on with the axes last used (X at first); an axis flyout beside the rail's mirror and lock buttons (shown while either is on) toggles X, Y and Z; turning off the last axis turns mirror off. x and z mirror across the opened file's own x = 0 and y = 0 planes (MagicaVoxel models are centred on their translation, and this keeps the prototype's X mirror; vxr z is the negated file y, so the file's y = 0 plane sits at vxr z = 1, not 0); y mirrors across the middle of the opened model's height, since mirroring across world y = 0 would put everything under the ground. A new scene is now centred on world x = z = 0 so its mirror planes sit in the middle of the map (before, its X mirror fell outside the map). With all three on, one cell becomes eight; images that coincide on a plane are set once.
  - **Axis lock (K)** is MagicaVoxel's brush "axis" option: drags stay on the plane across the locked axis through the pressed cell, whatever face was clicked, so a box on the ground with X locked builds a wall, and erase and paint drags stay in one layer instead of following the surface. K cycles X, Y, Z, off; the flyout's LOCK chips pick one directly. Cmd-K has Line brush, Center brush: circle and sphere, Mirror, Mirror X/Y/Z, Lock axis X/Y/Z and Cycle axis lock.
  - No render-side change, so the frame budget is unchanged (island at 3024x1964: 2.00 ms without the render corner, 3.87 ms with it).

- **Selection and transform** (`vxr_core::select`), MagicaVoxel's select mode in the Hybrid look. The mockups have no selection UI, so it reuses the axis flyout's parts.
  - **Select tool (S)**, the fifth tool on the rail (Lucide `square-dashed-mouse-pointer`). A drag draws a box on screen and selects every voxel whose centre falls inside it, hidden ones included, as MagicaVoxel's rectangle select does; a click (under 4 px of travel) selects every voxel of the clicked colour, and a click on empty ground deselects. Shift adds, Alt subtracts (the other tools' Shift erase and Alt pick do not apply to it). Brush shapes do not change the select tool: box and colour cover what the gap list ranks P1, and face or volume selection can come later. Cmd-A selects all, Escape deselects (after closing any open panel), Cmd-K "Select color" selects the current palette slot's voxels.
  - **Move** by pressing on a selected voxel and dragging: the selection slides on the plane of the face pressed (press a top face to move across the ground, a side face to move up), redrawn live like the span brushes, with the offset in the stats panel. Arrow keys nudge one cell along the ground axis closest to the view's right or forward direction, Shift-Up and Shift-Down one cell up or down. Moved voxels overwrite what they land on; cells moved outside the map are dropped (undo brings both back).
  - **The selection flyout** beside the select button (shown with the select tool or while anything is selected) has the count, a deselect button, ROTATE, FLIP and LOOP chips per axis, and fill, copy, cut, paste and delete. Rotate turns 90 degrees about the selection's bounds, keeping the centre (with odd size differences the offset truncates toward zero, so turning back undoes it exactly); flip mirrors inside the bounds; loop shifts one cell with wrap-around inside the bounds. With nothing selected they apply to the whole model, which the flyout says ("whole model"). Every one of these, and the Rotate, Flip and Loop X/Y/Z Cmd-K entries, is one undo step.
  - **Copy, cut, paste** (Cmd-C, Cmd-X, Cmd-V, the flyout, Cmd-K) use an in-app clipboard. Paste puts the copy with its bottom centre on the cell in front of the face under the pointer (beside the original when the pointer is off the scene), selects it and switches to the select tool, so the next drag moves it. Natively egui turns Cmd-C into a copy event and sends Cmd-V only when the system clipboard holds text, so Copy also puts a short text stand-in ("vxr: N voxels") on the system clipboard; the browser page forwards the keys themselves.
  - **Undo restores the selection.** The selection itself is not history (choosing what is selected is not an undo step, as in most editors), but every edit that moves or empties it (move, transforms, paste, delete, cut) records the selection before and after, so undo puts the voxels and the selection back together.
  - **Highlight:** selected voxels are tinted with the UI's accent and get a brighter line along their edges, in the march shader, from a bit mask in the brick map's own layout (16 words per brick slot) uploaded when the selection changes or, while something is selected, after any edit (brick slots can move). Cost on the island at 3024x1964: 2.01 ms per frame with nothing selected (unchanged), 2.38 ms with every voxel selected.

- **Model tools: hollow and fill inside** (`vxr_core::model`, Part 3 item 6), as in MagicaVoxel's and vengi's edit tools. Both act on the selection, or the whole model when nothing is selected (like the flyout's transforms), and each is one undo step.
  - **"Outside" is a flood fill**, not a neighbour count: a dense grid over the voxels' bounds, padded by one cell, is flooded through face neighbours from the padding. Hollow erases every voxel with no face on that outside, so a solid block keeps a one-voxel shell and sealed inner cavities' walls go too (they cannot be seen); fill inside puts the current colour into every empty cell the flood did not reach, so an open cup is not filled. Cells an unselected voxel holds are left alone. A neighbour-count hollow would leave cavity walls and could not tell a closed shell from an open one.
  - **UI:** two text buttons, Hollow and Fill inside, on their own row in the selection flyout above the fill/copy/cut/paste/delete icons (text, not icons: Lucide has no clear glyph for either, and "Fill inside" must not be confused with the paint-bucket fill of the selection), Cmd-K "Hollow" and "Fill inside", and a toast with the count ("Nothing to hollow" when the model is already a shell). No single-letter keys: MagicaVoxel has none for them and the free letters are kept for the camera and world editor items.
  - No render-side change (island at 3024x1964: 2.25 ms without the render corner, 4.32 ms with it while editing).
- **Model bounds: resize and crop to content** (`Scene::set_bounds`, `resize` and `crop`, Part 3 item 6).
  - **The bounds are the brick map's size.** `BrickMap` now keeps an exact size in voxels (the brick grid still rounds up to whole bricks, and cells past the size stay empty), so every edit, the ground and picking stop at the bounds, as in MagicaVoxel where a model's size limits where voxels go. A new scene is 128^3; an opened object's bounds are its model's size (until item 8 they were its voxels' extent plus 16 cells of room). A separate "bounds box" inside a bigger map was the alternative; it would need every tool to clip to it and would keep memory and march cost for space nobody can edit.
  - **Changing them replaces the map** with one at the new origin and size, and moves every map cell the scene remembers by the same shift: the selection, the clipboard's origin and every undo and redo step. History stays in map cells (no per-voxel world conversion on every edit), and a resize is rare enough that rewriting the history is cheap. The step records the old and new bounds (world origin, size and ground layer) with the voxels the shrink erased, so undo puts the map back first and then the voxels, and redo the other way round. The editor sees `Scene::reshapes` change, uploads the new map, restarts the render corner, cancels an export in progress, and moves the camera target by the shift so the view does not jump.
  - **Resize keeps the bottom and the centre** on X and Z (an odd change goes to the low side when growing and the high side when shrinking), as MagicaVoxel's size fields do. **Crop to content** fits the bounds to all voxels exactly, the ground moving up to the new bottom; it ignores the selection, since cropping to one part would silently erase the rest. Sizes go from 1 to 2048 per axis.
  - **UI:** Crop and Resize… text buttons as a second row under Hollow and Fill inside in the selection flyout (now 242 points tall), and a Bounds panel beside it (the colour editor's width, so X, Y and Z fields with up to four digits fit in a row like its R, G and B), aligned with the Resize… button, which shows on while the panel is open. The header shows the size; Enter in a field resizes, Escape closes. Cmd-K "Resize bounds…" and "Crop to content". No keys, as for hollow and fill.
  - **Saved as the model size** since item 8: an object's bounds are its model's `SIZE`, so resize and crop round-trip (see "World editor: model and world modes").
  - Island frame time at 3024x1964 after this change: 2.06 ms without the render corner, 4.29 ms with it while editing (the map is now cut to the exact size, no shader change).
- **Camera views: orthographic, isometric and side views** (`vxr_render::View`, `OrbitCamera::ortho` and `snap`, Part 3 item 7, first half).
  - **Orthographic is the same orbit camera with parallel rays.** Its view is `2 * distance * tan(fov / 2)` voxels tall, what the perspective view spans at the target, so switching keeps the model's size on screen and the wheel, pan and framing work unchanged. Rays start on a near plane 4096 voxels behind the target (outside any model, since bounds stop at 2048) and run along the view direction; the march, the path-traced corner (reset, trace and denoise) and picking all take the ray origin per pixel from the inverse view-projection when `eye.w` is 0, so perspective rays are unchanged. Depth of field in orthographic focuses at the same point as in perspective (the focus distance is moved back by the extra 4096).
  - **Up comes from the yaw**, not a cross with +y, so the camera can look straight down or up (top and bottom views); it equals the old basis everywhere else, and orbit now stops at straight up and down instead of 1.55 rad.
  - **Isometric is a view, not a third projection:** orthographic at yaw 45 degrees and pitch atan(1 / sqrt 2), so the three edges of a cube are equally long on screen. Orbiting leaves it (the flyout then shows Ortho); it counts as isometric from any of the four upper corners. Side views (front from +z, back, left from -x, right, top, bottom) keep the projection, as MagicaVoxel's do, and keep the target and zoom. Framing (`.`) keeps the projection, and keeps the angle when the camera is at a snap view.
  - **UI** (the mockups have none): a view button (Lucide `axis-3d`) at the bottom of the rail opens a View flyout built like the selection flyout, its bottom level with the button: the view's name, a Persp / Ortho / Iso segmented row and six side-view buttons showing their keys. Keys: O toggles orthographic, 1 to 6 front, back, left, right, top, bottom, 0 isometric (MagicaVoxel and Blender use number keys for views; these are free in vxr). Cmd-K has View options, Perspective, Orthographic, Isometric view and the six side views. The flyout has no single-letter key since O, the natural one, is the projection toggle.
  - MagicaVoxel's 26-view cube is not built: the six faces and isometric cover the gap list's P1 row, and the corner and edge views are reachable by orbit.
  - Island frame time at 3024x1964: 2.01 ms without the render corner and 3.89 ms with it while editing (before: 2.07 and 3.94, so the per-pixel origin costs nothing measurable); 3.58 ms isometric with the render corner.

- **Grid, ground and bounds frame** (`vxr_render::Guides`, Part 3 item 7, second half).
  - **Drawn in the march shader, in the editor view only.** The ground is the plane the clicks already land on (`Scene::floor`), seen from above: inside the bounds' footprint it is a flat shade lighter than the background, outside it fades into the background over twice the footprint's radius (MagicaVoxel's infinite ground, without a horizon line). The grid is a line on every voxel edge of the footprint, anti-aliased from the ground's size under one pixel and faded out where lines would be closer than about three pixels. The frame is the bounds box's twelve edges in the UI's accent blue, faint where a voxel hides them. The path-traced corner and the PNG export stay clean: they are the render, not the editor.
  - **The frame's edges are binned on the CPU.** Testing all twelve edges in every pixel cost 0.6 ms at 3024x1964 (0.05 ms per edge), so `set_camera` projects the edges, clips them to the near plane and the view, and marks a bit per edge in each 32-pixel tile they pass near (a storage buffer); a pixel tests only its tile's edges, usually none. The grid needs no neighbours: the footprint is a pixel across the ray and stretched by 1 / |d.y| along it, computed from the ray itself.
  - **All three are on by default** (MagicaVoxel shows its frame and grid by default) and toggle from three buttons under the side views in the View flyout (now 210pt tall). G toggles the grid (free, and MagicaVoxel users expect a grid key); the ground and the frame have no key, since B and F are brushes, and are in Cmd-K as Show ground and Show bounds, with Show grid. They are view settings, not edits: no undo step, not saved.
  - `Guides` defaults to off, so the renderer's pixel tests against the CPU ray cast stay exact; a GPU test checks each guide on its own.
  - Island frame time at 3024x1964: 2.15 ms without the render corner and 4.48 ms with it while editing, against 2.00 and 3.97 with the guides off in the same run (the opened island's bounds include the 16-voxel padding until item 8 saves the model size).

- **World editor: the data model and its save** (`vxr_core::World`, `vxr_vox::Tree`, Part 3 item 8, first step; not in the editor yet).
  - **Two modes, as in MagicaVoxel.** The editor will keep editing one model at a time with every existing tool on one brick map (`Scene::map`), and a world mode will show every object and move, copy, group and hide them. Editing objects in place inside one flattened map was rejected: a linked copy would need each edit replayed at every copy's cells, moves would have to re-resolve overlaps cell by cell, and the history (stored in map cells) would mix objects.
  - **Objects and groups are a tree read from the scene graph** (`Tree::read`): an object is an nTRN over an nSHP, a group an nTRN over an nGRP, each with its name, hidden flag, layer and base transform kept in the file's z-up axes, so saving never converts a transform. Models are brick maps in vxr's y-up axes (file voxel (x, y, z) is model cell (x, z, sy - 1 - y)), the form the model editor edits. Linked copies share a model (editing it changes every copy, as in MagicaVoxel); a duplicate deep-copies it. Nodes a file shares between parents become separate nodes, so each copy can move on its own.
  - **Saving patches the opened file** (`Document::set_tree`): an nTRN is rewritten only when its name, hidden flag, layer or transform changed, and then only those keys (keyframes, `_frm_t` and unknown keys stay); an nGRP only when its children changed; an nSHP only when its model changed; a model only when its size or voxels differ; a `LAYR` only when its name or hidden flag changed. New nodes and models go after the last node and model chunks, nodes no longer in the tree are dropped, and every other chunk keeps its bytes, so an unedited save is byte-identical. The result is read back and compared; when it cannot be written that way (a file without a scene graph, or a model over 256 on an axis) the models and scene graph are rebuilt from the tree with names, flags and layers, and a model over 256 becomes a group of blocks named after the object.
  - Tested on every generated fixture and the island (unedited saves byte-identical, world voxels equal to the flattened view, edits saved and reopened with the same outline and voxels, non-geometry chunks unchanged), with a new `22-world` fixture (named objects, a nested group, three linked copies of one model, a hidden layer and a hidden node).

- **World editor: model and world modes in the editor** (Part 3 item 8, second step: `Scene::edit_object`, `show_world`, `edit_world`, Tab).
  - **The map holds one thing at a time.** In model mode it is one object's model in world axes, rotated and placed where it shows (`World::object_map`), so every tool, the selection, mirror and the history work unchanged, and the view does not move when switching. In world mode it is every shown object composed with the overlap rule; voxels cannot be edited there (`Scene::put` refuses), and world edits (move, copy, group, hide, layers) go through `Scene::edit_world`, one undo step each, which recomposes the map.
  - **The bounds are the model's size**, as in MagicaVoxel: an opened object's bounds are exactly its `SIZE`, the ground is its bottom and the mirror planes its middle. Leaving a model (or saving) stores the map back (`World::store`): the model takes the map's bounds as its size, and when a resize or crop moved its corner every object showing the model gets the matching shift in its own frame, so nothing moves in the world and linked copies stay put. The 16 cells of room an opened file used to get are gone: an unedited model must save byte-identical, and a model one voxel tall cannot grow upward until it is resized, as in MagicaVoxel.
  - **Undo follows the edit.** Each step records where its cells are (`history::At`: a new scene's map, the world, or one object's model). Undo and redo of a step made elsewhere first switch there (storing the current model), so a model edit undone from world mode goes back into that model. A world step keeps the tree before and after and the models it added (a duplicate's own), which undo drops and redo puts back. A resize translates only the steps of its own map. Switching itself is not a step.
  - **Tab** switches: from a model to the world, and from the world back to the object last edited (the first object at first). egui moves keyboard focus on Tab before the UI could consume it, so `Editor::frame` takes Tab out of the input unless a text field is typing. Cmd-K "World mode / edit model". A new scene has no world yet (Tab says so); a file with one object can switch, and the island looks the same in both modes.
  - **Next:** groups and layers in the UI (picking, dragging, duplicate and instance landed in the third step below, the scene tree in the fourth).
  - Island frame time at 3024x1964: 2.15 ms without the render corner, 4.29 ms with it while editing (no render change; the island's map is now its exact 128x31x128 instead of 160x63x160).

- **World editor: pick, move, duplicate, linked copy and delete objects** (Part 3 item 8, third step: `Scene::pick`, `put_world`, `World::object_at`, `duplicate`, `remove`).
  - **Any tool picks in world mode.** A click picks the object whose voxel shows under the pointer (the overlap rule decides, `World::object_at`) and shows its voxels with the selection highlight; a click on nothing picks nothing, as does Escape. Picking is not an undo step (MagicaVoxel's object selection is not either). The pick survives the recomposed map after each world edit and undo, and is dropped when its object leaves the tree. Leaving a model with Tab picks that object, and Tab from the world edits the picked object (MagicaVoxel: select, then Tab), else the one last edited.
  - **Drag moves the picked object** on the plane of the face pressed, live, as one undo step: `Scene::put_world` changes the world inside an open edit and `commit` closes it, the way voxel strokes work. The drag is tracked in world cells because the composed map's origin moves as the object does; the editor shifts the camera at once so the pointer keeps its world point. Arrows nudge along the ground (turned to the view, as for selections) and Shift-Up and Shift-Down raise and lower, one step each. The selection flyout is hidden in world mode, since its commands edit voxels; voxel commands there say to Tab into an object.
  - **Cmd-D duplicates, Cmd-Shift-D makes a linked copy** (MagicaVoxel's instance, sharing the model, so an edit shows on every copy), Backspace deletes; Cmd-K has Duplicate object, Linked copy (instance) and Delete object. The copy goes beside the original on +X with one cell between and is picked, so it shows at once (a copy in place would hide behind the original). A deleted object's model stays in the world (and the file) so undo can bring it back; an unused model costs a few bytes and MagicaVoxel ignores it.
  - **The hint bar** in world mode lists Click pick, Drag move, and with a pick Arrows, Cmd-D, Cmd-Shift-D, Backspace, then Tab and Right-drag.
  - **Browser check fixture:** `crates/vxr-web/check` writes the generated `22-world` file with the new `vxr-vox` example `fixture` into a temporary folder served under `/__fixtures/`, so `dist/` stays the site and no `.vox` is committed; `check.js` opens it through the file input.
  - Island frame time at 3024x1964: 2.07 ms without the render corner, 4.35 ms with it while editing (no render change).

- **World editor: the scene tree** (Part 3 item 8, fourth step: `Hybrid::tree_panel`, `editor::tree_rows`).
  - **Where it sits.** Diorama's (C) tree, kept for Hybrid: a 212-point panel beside the tool rail, top-aligned with it, shown only while the file has two objects or more (a single model and a new scene show none, as decided for Hybrid). The rail's flyouts (mirror and lock, selection, Bounds, View) open beside the tree instead of over it. It shows 14 rows and scrolls with the wheel past that.
  - **Rows.** Every node under the root in tree order (the order that also decides overlaps), indented 14 points per group, with Lucide `box` for an object, `link` for a linked copy (a model shown by more than one object) and `folder` for a group, the name (or "object N" / "group N"), the model's size in voxels as the Bounds panel shows it, and an eye. Rows that do not show (hidden, or under a hidden group or layer) are faint; the picked object's row (or the edited object's, in model mode) has the accent background.
  - **What a row does.** A click picks the object in world mode, and in model mode edits that object's model (switching objects without going through the world). In world mode the eye (shown on hover, always when hidden) hides and shows, H does it for the picked object, and a double-click or Cmd-K "Rename object" renames in place (Enter or a click away keeps, Escape cancels, an empty name clears it so the file has no `_name`). Each is one world undo step and saves as the nTRN's `_hidden` and `_name` keys only. Hiding and renaming are world edits, so the eye and rename are not offered in model mode. Groups are listed but not picked yet: picking and moving groups, ungrouping and the layer controls are the next step.
  - **Escape in the field.** egui drops keyboard focus on Escape before the UI runs, so a plain lost-focus check cannot tell Escape from Enter; `Hybrid::keys` consumes Escape while a rename is open and cancels it.
  - Island frame time at 3024x1964: 1.98 ms without the render corner, 3.99 ms with it while editing (no render change; the island is one object, so no tree).

## What the prototype proved

`prototype/` is a throwaway three.js editor (see the README). Findings worth keeping:

- Sparse 32^3 chunks in a map, greedy meshing with per-vertex ambient occlusion, and only dirty chunks remeshed on a per-frame budget: a single edit remeshes 1 to 4 chunks in about 1 to 7 ms.
- Meshing 145k voxels takes about 0.11 s and 3.9M voxels about 0.39 s, on the CPU in JavaScript.
- Recoloring through a palette texture read in the vertex shader makes palette edits instant, with no remesh. Keep this trick.
- `.vox` round-trip of its own files was lossless (0 mismatches over 145,064 voxels); scenes over 256^3 split into 256^3 models and read back intact. It ignores model rotation, `MATL` materials and layers, and was not checked in MagicaVoxel itself.
- The embed as a web component: shadow DOM, its own orbit that never captures page scroll, and rendering only while on screen.
- Island draws 32k triangles in 18 draw calls; the 3.9M-voxel terrain draws 595k triangles in 248 calls. FPS was not measured on real hardware.
