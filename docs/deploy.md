# Deploy

How the browser editor at https://vxr.jrnxf.co is built and deployed. For the owner and for anyone who hosts their own copy.

- The browser editor at https://vxr.jrnxf.co deploys itself: Cloudflare Workers Builds builds every push to `main` and deploys it, and builds every other branch as a preview version that does not go live (the `Workers Builds: vxr-preview` check on a pull request). Both run `crates/vxr-web/cloudflare-build`, which installs the same tools as `nix/`, pinned by version and sha256, installs the Worker's npm packages and runs `crates/vxr-web/build` with them. The production deploy command applies the D1 migrations first (`npx wrangler d1 migrations apply vxr --remote && npx wrangler deploy`). The build variables are `TURNSTILE_SITE_KEY` and `NODE_VERSION`, and the Worker's secrets `BETTER_AUTH_SECRET`, `TURNSTILE_SECRET_KEY` and `RESEND_API_KEY` (without them the site works with sign-in off).
- Branch builds go to a separate Worker, `vxr-preview` (`env.preview` in `crates/vxr-web/wrangler.jsonc`), with its own D1 database `vxr-preview` and R2 bucket `vxr-projects-preview`, on workers.dev only, so a branch never reads or writes production accounts or projects. A version uploaded to the `vxr` Worker keeps that Worker's secrets, and Workers Builds always uploads to the Worker a trigger belongs to, so the branch trigger lives on `vxr-preview`, not on `vxr`. It was set up once, in this order (steps 1 to 4 are done; redo them only to rebuild the environment):
  1. `npx wrangler d1 create vxr-preview`, and put the `database_id` it prints into `env.preview` in `wrangler.jsonc`.
  2. `npx wrangler r2 bucket create vxr-projects-preview`.
  3. `npx wrangler d1 migrations apply vxr-preview --env preview --remote`, then `npx wrangler deploy --env preview` once to create the Worker. Migrations always run before any secret is set, so sign-in never starts on a database without its tables.
  4. In Workers Builds, connect `vxr-preview` to the repository with a branch trigger (every branch but `main`, the same build command, root directory and build variables as `vxr`) whose deploy command is `npx wrangler versions upload --env preview`, and delete the branch trigger on `vxr`. Migrations stay out of branch builds; a new migration is applied to `vxr-preview` by hand, as in step 3.
  5. Not done, optional, for sign-in on previews: preview-only secrets with `npx wrangler secret put <NAME> --env preview`, never production's values, and Cloudflare's always-pass Turnstile test keys, since the production widget only accepts its own host: the build variable `TURNSTILE_SITE_KEY=1x00000000000000000000AA` on the `vxr-preview` trigger (`cloudflare-build` otherwise uses production's) and the secret `TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA`.
- `crates/vxr-web/deploy` still deploys by hand from a clean `main`, through the nix dev shell.
