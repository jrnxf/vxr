# vxr

fast voxel scenes: an open-source voxel scene editor (Rust, wgpu) with a one-tag web embed.

## Stack

- Rust core on wgpu (Metal, Vulkan, DX12, WebGPU in the browser). Desktop first; the browser build and the embed come from the same code. No server.
- UI drawn in Rust with egui (picked by test 3, see `docs/decisions.md`) so the Hybrid UI runs native and in the browser.
- The real build is the Cargo workspace at the root (Phase 3, in progress). Run everything through `./dev <command>`, a Nix dev shell (`nix/flake.nix`: Rust with the wasm32 target, wasm-bindgen, wasm-opt, twiggy, brotli).
- The Phase 2 spikes in `spikes/` build separately through `spikes/dev <command>` (`spikes/dev --fuzz` adds nightly and cargo-fuzz). Wrap timed GPU runs in `spikes/gpu-lock` so benchmarks never share the GPU.

## Where things live

- `crates/vxr-vox`: the `.vox` codec (from `spikes/vox`), with `material.rs` mapping `MATL` dicts to typed materials and `tree.rs` reading the scene graph as an editable tree of objects and groups with layers (`Document::tree`, and `set_tree` writing it back touching only what changed). `crates/vxr-core`: the editable scene (brick map, palette and per-slot materials, undo/redo, the editing tools in `tools.rs` and selection and transform in `select.rs`, hollow, fill inside, resize and crop in `model.rs`, the OBJ export's greedy quads, text and palette texture and the PNG slices in `export.rs` (the bounds are the brick map's exact size, `Scene::set_bounds`), `.vox` open and lossless save through `vxr_vox::Document::set_world` and `set_material`, and in `world.rs` the world of several objects (groups, linked copies, layers; move, copy, group, ungroup; `object_map` and `store` place a model in world axes and put it back) saved through `set_tree`; `Scene` holds the world of an opened file and its map is one object's model or the composed world (`edit_object`, `show_world`, `edit_world`)), no GPU. `crates/vxr-render`: the GPU renderer (from `spikes/engine`: compacted brick map upload, `trace_h` march, blit, orbit camera in perspective or orthographic with the snap views in `camera.rs`, the ground, grid and bounds frame drawn in `march.wgsl` (`Guides`)); its tests render on the real GPU and compare every pixel with the CPU ray cast, and skip when there is no adapter; `preview.rs` is the live path-traced corner (from `spikes/preview`), also used at the export size; `gpu.rs` has the non-blocking `Readback`. `crates/vxr-app`: the desktop editor (binary `vxr`): `editor.rs` (scene, camera, gestures and drawing, no window; `tree_rows` and `layer_rows` build the scene tree's rows and its LAYERS list), `ui.rs` (the Hybrid UI in egui, from `spikes/ui`), `render.rs` (Render panel settings and the PNG export), `files.rs` (re-exports `vxr_core::files`: the OBJ export's files, the PNG slices and the zip the browser downloads), `native.rs` (winit window, file dialogs), `shot.rs` (the headless check). `crates/vxr-web`: the same `Editor` on a WebGPU canvas (`src/web.rs`) and its page (`www/index.html` and its script `www/app.js`), which forwards input, opens files through a file picker and downloads saves.

- `assets/logo/`: the logo as SVG (the cube, the wordmark and the lockup, each for dark and light backgrounds, and the app icon); `docs/decisions.md` "Logo" has the colours and sizes.

- `docs/plan.md`: what to research and test next, in order. Ask the owner before starting each phase.
- `docs/decisions.md`: every settled decision and why. Update it when a decision changes; do not duplicate it here.
- `docs/research/`: Phase 1 desk research, one file per topic. `docs/research/magicavoxel-gap.md` lists every MagicaVoxel feature with vxr's status and priority; update its row when a feature lands. `docs/research/ai.md` is the AI research and proposal (assistant and `vxr mcp`); its mocks and screenshots live in the git-ignored `.scratch/ai-mocks/` and are never committed.
- `docs/market-research.md`: the market case. Reference only.
- `ui-directions.html` and the prototype screenshots: the UI options that led to Hybrid (direction D) and the mockups test 3 compares against. Reference only, in `vxr-design-references.zip` on the `design-references` GitHub release, not in git.
- `spikes/`: Phase 2 risk tests (engine, preview, vox, embed) and Phase AI risk tests (`ai-<name>`), each with a `RESULTS.md`. Throwaway, but the engine and the `.vox` codec are the starting point for Phase 3.
- `prototype/`: run `node prototype/src/build.mjs` once to create `prototype/demo/` (git-ignored), including the island `scene.vox` the spikes load. A throwaway three.js editor used to try the feel. Not the real build; mine it for ideas (chunking, greedy meshing, palette-texture recolor, `.vox` I/O), do not extend it.

## Keep the repo small

- The owner wants a lean repo. Do not commit heavy files (screenshots, videos, recordings, benchmark dumps, large test data, built bundles) when they can be avoided: git history keeps them forever.
- Put them in a zip on a GitHub release (`gh release create` or `gh release upload`) and link the release from the docs, or regenerate them from a script.
- Small files the code needs (a test fixture of a few KB, a poster image for the embed) are fine. Ask before committing anything over about 200 KB.
